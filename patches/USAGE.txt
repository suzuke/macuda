macOS 15 / RTX 3060 compatibility branch

Offline checks (safe to run while other jobs use the Mac):
  sh tools/test-offline-compat.sh
This compiles one small C test with AddressSanitizer/UndefinedBehaviorSanitizer
and runs Python fixtures. It does not access the GPU, start Docker, or build
llama.cpp. No downloaded firmware is required for these tests.

The FWSEC signature is selected automatically from the card's fuse version
and VBIOS version mask. With ARCH unset, setup.sh and install.sh pick the
build architecture from the connected card's PCI device id (sm_86 for the
tested RTX 3060; `sh setup.sh arch` prints the choice). No card or an
unrecognised one falls back to sm_120a and says why; a set ARCH always wins.
At run time libtinynv refuses a cubin the card cannot run (for example
sm_120 code on GA106), naming both architectures; TINYNV_ARCH_CHECK=0
overrides for diagnostics. Each build still targets one architecture.

One binary for several cards (ARCH=multi):
  ARCH=multi sh install.sh
builds sm_86 (Ampere, Ada) and sm_120a (Blackwell) device code into every
fatbin and embeds both families' copy/GEMM/keep-alive kernels. At start-up
the runtime reads the card's architecture register before booting and loads
the image that runs on it. Binaries go to cuda-shim/build/bin-multi. The
device compile takes about twice as long, and the archive is about twice the
size (386 MB vs 181 MB). Measured on the RTX 3060 only:
  - opverify passed 450/450;
  - the 16-token text was byte-identical to the sm_86 build;
  - speed matched the sm_86 build (A-B-B-A, -t 1).
The Blackwell half has only been tested offline (test_pick_image).

Run one GPU operation at a time. Follow README's operating protocol.

CPU thread count (llama-bench / llama-server -t)

llama.cpp keeps the input embedding on the CPU, so every token wakes the
CPU threadpool even with -ngl 99. The default -t equals the P-core count
(12 on the tested 16-core M3 Max). When other processes occupy the P-cores,
decode slows sharply. The measurements point to this CPU threadpool rather
than the driver (see VALIDATION.txt, 2026-11-18).
  Full offload (-ngl 99):  use -t 1.
  Partial offload:         use fewer threads than P-cores (-t 4 was best
                           of the values tried).
Only llama-bench with -t 1, 4 and 12 was measured, on Qwen2.5-7B Q4_K_M.
llama-server takes the same -t flag but was not measured. Example:
  BENCH_ARGS="-t 1" QUIESCE=1 BIN="$PWD/cuda-shim/build/bin-sm_86" \
    sh tools/nv_shim_step.sh A bench models/Qwen2.5-7B-Instruct-Q4_K_M.gguf
The runner's default stays -t unset so results remain comparable with the
published author numbers.

Profiling report and ABBA tools (default: no GPU work)

Summarize an existing raw driver log:
  python3 tools/profile-report.py logs/shim-probe-YYYYMMDD-HHMMSS.log
The JSON separates throughput rows from timestamp-quality warnings. Zero,
reversed or >100 ms printed intervals, discarded samples and negative
microsecond durations are flagged. It does not repair timestamps or claim
that an apparently sane clock is calibrated. Raw logs remain unchanged.

Prepare a delta-delivery comparison without executing it:
  python3 tools/ab-bench.py --model models/Qwen2.5-7B-Instruct-Q4_K_M.gguf
The default prints an A-B-B-A plan: delta delivery 0 versus 1, identical
pp256/tg128/r3 settings. A chain-depth plan instead uses:
  python3 tools/ab-bench.py --model models/Qwen2.5-7B-Instruct-Q4_K_M.gguf --knob TINYNV_CHAIN_DEPTH --a 64 --b 128

Only add --execute when GPU work is intended. It runs four benchmark
processes sequentially under the existing runner, requires successful
quiesce and postflight, and stops after a failed arm. It records model and
binary SHA256, source state, raw-log references, summaries and load averages
in a unique logs/ab-* directory. Model hashing reads the entire model once.
Supported tuning variables are deliberately limited. The tool removes
inherited CUDA/driver tuning variables so hidden overrides cannot change
one arm. It does not stop unrelated workloads or change global settings.

Use --profile to instrument BOTH arms in a separate diagnostic experiment;
do not compare profiled numbers directly with unprofiled numbers.
Its scheduler lock excludes other instances of this tool only. Ensure no
other GPU client is running. Do not delete .dart-stale/.dext-seen to force a
run through. Follow README's power and operating instructions.

Results are performance measurements, not correctness certification.
Before keeping a faster option, run operator and deterministic-output
checks under that option. ABBA reduces order bias but cannot eliminate
background-load changes or thermal drift. The runner orchestration has
been prepared offline; new A/B GPU experiments have not yet been executed.
